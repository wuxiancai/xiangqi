# 中国象棋学习与对弈软件：产品与技术方案

## 目标与原则

交付一个无需安装、可在桌面和手机浏览器运行的中文单页应用。首版优先完成规则正确、棋谱可回放、离线可用的学习与本地对弈闭环；网络 AI、数据同步及复杂棋谱格式都通过边界清楚的扩展接口接入。所有棋谱标明来源与授权状态，未核实来源或授权的内容不得冒充公开棋谱发布。

## 首版范围（Must）

1. **Web 应用及结构**：静态单页应用，HTML/CSS/JavaScript 原生模块；不引入前端框架，除非后续实测复杂度使其成为必要。模块划分为 `board`、`rules`、`game`、`notation`、`library`、`storage`、`ai`、`ui`。提供本地开发启动方式和部署说明；上线时通过任意静态 HTTPS 托管访问，无需客户端安装。另提供自托管一键部署/停止脚本：Linux 必须由 systemd 管理；macOS 使用 launchd，Windows 使用任务计划程序。静态资源仍可单独部署到 HTTPS 静态托管，无需运行这些脚本。
2. **完整规则与走子**：实现中国象棋棋盘、红黑双方棋子及合法走法，包括车、马、相/象、士/仕、帅/将、炮、兵/卒限制，蹩马腿、塞象眼、炮架、九宫与河界、将帅照面、自将判定、将军、将死、困毙和回合状态。落子只接受规则模块给出的合法着法；悔棋、重新开始及结束状态可用。规则层不依赖渲染层。
3. **棋谱库**：内置不少于 100 盘经人工或脚本校验的棋谱：古谱至少 30 盘（覆盖《梅花谱》《橘中秘》《适情雅趣》），近现代对局至少 30 盘，开局/残局教学谱合计至少 40 盘。类别可多选，按标题、作者/棋手、类别检索。古谱须标明所用版本/转录来源；现代棋谱须登记来源与使用许可，无法核实者不发布。每盘均可从首着完整播放并通过规则校验。
4. **打谱学习**：提供上一步、下一步、跳到开局、跳到末尾、自动播放、暂停、速度调整、着法列表定位。速度设为每步 0.25–5 秒（250–5000 毫秒），允许测试 0.25、1、5 秒边界。每个关键着法可显示不超过 50 个中文字符的说明；内置说明为主，AI 生成说明仅作可选补充且需标为 AI 内容。
5. **对弈**：本地双人轮流、用户执红/执黑对电脑两种模式；任意模式支持翻转棋盘 180 度。显示当前行棋方、双方身份、走棋历史、悔棋/重开及胜负原因。用户选黑方时电脑先走红方。
6. **本地持久化**：设置、导入棋谱及对局保存在浏览器 IndexedDB；无后端也能访问内置棋谱及完成主要功能。提供清理/导出个人数据入口；浏览器清理站点数据会移除本地数据，首版明确提示此限制。
7. **响应式与无安装访问**：支持当前稳定版 Chrome、Firefox、Edge、Safari；手机端最低验收视口为 360×640 CSS 像素。窄屏采用棋盘优先布局，棋子点击/触摸可完成选子与落子，主要按钮触控目标至少 44×44 CSS 像素；不要求悬停操作，页面不得出现横向溢出。平板与更大窗口自适应利用空间。
8. **AI 接入边界**：定义统一 AI provider 接口，首版只交付一类 OpenAI-compatible Chat Completions 适配器（可连接提供兼容接口的服务），密钥由用户在本机配置。Claude、各国产模型的专用协议适配为后续项。AI 分析/着法必须经过本地合法着法校验；非法或超时响应不执行并提示。用户密钥只保存在当前浏览器本机，不发到本项目服务器；浏览器直连会受到供应商 CORS、配额和密钥暴露风险影响，UI 必须提示。禁止把密钥写入源码、日志或棋谱。

## 棋谱格式决策

- **默认内部及持久化格式：版本化 JSON（`xiangqi-study/v1`）**。标准 PGN 面向国际象棋，不作为中国象棋原生默认格式；自定义 JSON 能直接表达中文棋子/坐标、结果、来源授权、变例和逐着注释。
- 每盘结构至少包含 `schema`、`id`、`title`、`category[]`、`players`、`result`、`source`（含 `rights`）、`initialPosition`（标准开局或含 side-to-move 的中国象棋 FEN）、`moves[]`（ICCS 起止坐标）、`annotations`（ply 到短说明）、`tags[]`。坐标定义固定为红方视角文件 a–i、横线 0–9；版本升级须保留迁移器。应用内部使用结构化着法，不以 SAN/中文记谱字符串作为规则输入。
- **导入范围**：内部及持久化格式仍是 `xiangqi-study/v1` JSON；另通过可编辑文本转换器导入 XQF 主线、TXT/MD、常见 PGN/ICCS/FEN 文本、DOCX、PDF 和常见图片。XQF 在本机解码并逐着匹配合法着法；OCR/文档解析后同样校验，错误时不部分导入。每文件最大 500 MiB；未列出的专有格式、旧版 DOC、加密文档、从棋盘局面截图直接识谱不保证支持。浏览器按需从 CDN 下载 PDF/DOCX/OCR 引擎，文件本身不上传。
- **残局局面**：v1 支持标准初始局面及中国象棋 FEN 自定义初始局面，包含 side-to-move 字段；这是残局教学棋谱的必要能力。转换器必须校验 FEN 行数、每横线 9 格及双方将帅。
- **切换条件**：JSON 仍作规范内部模型；XQF 已支持主线导入，后续仅在变着树需求明确且解析可靠时扩展。PGN 仅在目标中国象棋工具链形成稳定约定后增加转换适配。迁移不得改变规则层接口。

## 关键着法及解说规则

- 首版关键着法由编辑提供，不让未经验证的 AI 判定成为发布内容。符合以下任一项标记：将军、吃子、将死/困毙；谱中显式标注的主变转折/弃子/战术着；或在对应局面列入参考引擎最佳着法且与次选评估差达到经测试确定的阈值。前三项由走法/注释确定，最后一项依赖后续引擎分析，不是首版内置标记的必要条件。
- 内置解说简述“走子意图/直接威胁/防守目的/常见应对”之一，中文长度按 Unicode 字符计 1–50 字；无可靠资料时不编造，显示“暂无解说”。逐条校验超长说明；AI 生成也必须限长并经合法着法与上下文校验，失败则不展示或保留原文。
- 首版验收：每盘至少为已标记关键着法提供说明或明确的“暂无解说”；至少 95% 解说不超过 50 字，超长内容导入时拒绝或明确报错；非关键着法不强制生成评论。

## AI 棋力目标、等级及降级

- **区分能力**：语言模型负责自然语言局势说明，不单独承担可靠的棋力承诺；实际走子首选受规则约束的象棋引擎适配器（优先评估有明确许可、可在浏览器运行的 WASM 引擎）。强度等级不能用模型名称直接等同 Elo。首版接口保留引擎能力，且在完成引擎选型/许可证/浏览器基准之前，界面不得声称已达到“业余高手以上”。
- 目标等级标签为入门、业余、高手、最强。引擎接入后分别映射到引擎经验证的限制参数（搜索时间/深度/候选噪声）；各档实际对局胜率/棋力须通过固定基准对局集估计并在 UI 说明为近似值。不得跨供应商宣称等级等价。
- 首版外部 AI 仅保证“分析与建议接口可调用”，不保证外部模型对弈达到业余高手。AI 建议从规则引擎枚举合法着法，外部模型只能分析这些候选并解释；超时、拒答、无效 JSON、非法着法一律降级为不提供建议/显示本地合法着法，不能伪称高手 AI。后续通过许可审查和基准赛接入 WASM 引擎，再开放四档强度。分析请求由用户显式触发，设置响应超时和调用/费用提示，不自动发送整盘个人数据。
- AI 可测试判据：适配器 mock 测试覆盖成功、超时、供应商错误、拒答、非法输出；任何被应用执行的建议必须属于当前合法着法集合。引擎上线门槛：固定公开/自建测试集至少 100 局或等量测试位置，无非法着法；对比明确标定的业余高手基线，目标等级达到预先定义的胜率阈值（建议对称对局 50% 置信区间下界不低于 45%），否则标注为实验性并降级为分析建议。样本、对手、参数与结果随版本记录。

## 渲染与技术选择

- **默认棋盘渲染 SVG**：矢量缩放、棋子点击区域与辅助标记易测、易访问。落子规则、棋局状态、记谱和绘制分层。棋盘保持正方形，坐标与可视方向通过视图映射处理，翻转不修改底层局面。
- **切换条件**：仅当目标设备压力测试证明 SVG 无法满足交互/绘制性能（例如连续操作响应 p95 超过 100 ms）且 Canvas 原型达标时，才切 Canvas；需补齐键盘/屏幕阅读器语义与独立命中测试。禁止为性能推测提前并列实现两套渲染器。
- **前端**：HTML/CSS/JavaScript ES Modules，依赖越少越好；所有规则纯函数化便于测试。静态资源通过 HTTPS 部署；首版不需要应用服务器。
- **状态**：内存中维护当前棋局，IndexedDB 存用户数据。定义 `StorageRepository` 接口，以便未来替换数据库。
- **数据库切换条件**：当需要跨设备同步、账号/权限、多用户分享、服务器备份/恢复或协作管理时，引入后端 API 和 PostgreSQL（建议默认）及认证/迁移。影响范围仅为 repository/API、账号权限、部署与隐私/备份策略；UI 与规则领域模型保持稳定。首版不做账户、云同步、服务端棋谱编辑、多人联网对弈、社交、在线支付及服务端存储用户 API 密钥。

## 检索与界面

- 棋谱按 `古谱`、`现代对局`、`开局`、`残局` 分类；允许一盘多分类。关键字段包含标题、棋手、年代、来源、许可、标签。
- 首屏提供学习（棋谱库/回放）与对弈入口；选择模式、执方后进入棋盘。棋盘旁显示回放控制/历史，移动端改为棋盘下方抽屉或列表。
- 空状态、错误导入、AI 不可用、无解说、存储不可用均应有中文反馈；不得用假数据掩盖缺失内容。

## 首版验收清单

1. 棋谱数量不少于 100 且满足各类别最低数量，三个指定古谱均可检索；每盘全谱可重放，非法着法数据为零，来源/授权字段完备。
2. 八种棋子和特殊限制均有规则测试；覆盖自将不合法、照面、将军、将死、困毙及红黑胜负；同一局面合法着法结果与参考数据一致。
3. 上一步/下一步/首着/末着/自动播放、暂停和 250–5000 ms 速度均可操作，暂停/换谱/到末尾时定时器正确清理；关键着法说明不超过 50 字或显示空说明。
4. 浏览器 JSON/XQF/其他格式导入拒绝无效、非法着法、超 500 MiB 文件；有效棋谱可重载后留存并在棋谱库单独筛选。
5. 本地双人及 AI 对局、红黑选择、黑方先走、翻转、当前回合、历史、悔棋与终局原因正确。
6. Chrome/Firefox/Edge/Safari 桌面稳定版及 iOS Safari/Android Chrome 的手工冒烟通过；360×640 视口无水平溢出、触控目标至少 44 px、无需悬停完成主要流程。
7. 任意 AI 建议若被展示为可执行着法，必须由规则校验通过；密钥不离开浏览器到本项目服务，不出现在日志。明确报告模型服务不可用和棋力未认证状态。

## 可延后项（Should/Could）

- XQF 变着树导入、PGN/ICCS 文本及其他棋谱格式导出。
- Claude/厂商专用及国产模型逐家适配；首版一个 OpenAI-compatible 接口。
- 认证、云数据库、跨设备同步、在线房间/联网双人、观战与分享。
- 经过许可/基准认证的 WASM 引擎及正式“业余高手以上”棋力承诺；四档 UI 标签不代表首版已兑现相应棋力。
- AI 自动批量注释、全谱深度分析、开局库/残局库扩充、训练题生成、用户评分/排行榜。
- PWA 安装/离线缓存增强、原生应用、国际化、统计分析及商业化功能。

## 交付阶段

1. **规格与内容审查**：确认数据来源/授权表，建立 JSON schema、坐标约定、规则测试局面和架构骨架。
2. **规则纵切**：完成局面、合法着法、将军/终局判断与自动化测试；这是所有模式的前置条件。
3. **可玩单页**：SVG 棋盘、选子落子、翻转、本地双人、历史与 IndexedDB。
4. **学习闭环**：整理并校验 100 盘棋谱，检索、导入、回放、变速、关键着法说明。
5. **AI 接口**：统一 provider、密钥设置与分析/建议、输入输出校验、错误降级；引擎能力单独列为认证门槛。
6. **适配与发布**：桌面/手机验收，HTTPS 静态部署、备份/导出说明、隐私与来源说明。

首版完成的定义是上述 Must 与验收清单全部通过；后端数据库和未列入首版的供应商适配不得成为发布阻塞条件。
